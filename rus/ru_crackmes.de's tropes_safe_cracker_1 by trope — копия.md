## 1. Подготовка

1. Открываем файл в **x32dbg**.
2. Переходим в **Handles**, жмём несколько раз **Run**, чтобы появилось окно программы.
3. В окне Handles нажимаем **ПКМ → Refresh**.

## 2. Ставим хук на клик

При клике ЛКМ по кнопке:

- сама кнопка получает `WM_LBUTTONDOWN` / `WM_LBUTTONUP` (`0x0201` / `0x0202`);
- родительскому окну (диалогу) кнопка посылает `WM_COMMAND` (`0x0111`), в `wParam` которого:
  - младшее слово — **ID кнопки**;
  - старшее слово — код уведомления (`BN_CLICKED = 0`).

> ⚠️ Это **два разных сообщения**, их не складывают. Запись «`WM_COMMAND + 0x220`» — некорректна.

В Handles выбираем кнопку **"Open"** → ПКМ → **Message breakpoint → WM_LBUTTONUP**. Это удобный способ поймать момент клика именно по этой кнопке.

Далее жмём **Open** в крякмисе — нас кидает в недра `User32.dll`. Выбираемся оттуда через **Run to user code (Alt+F9)**.

**Что происходит:** при нажатии на любую кнопку нас кидает в обработчик диалога (`DialogProc`). Он смотрит на `msg` (`[ebp+C]`): если это `WM_COMMAND` (`0x111`), то дальше смотрит на `wParam` (`[ebp+10]`) — младшее слово которого содержит **ID нажатой кнопки**.

| Ситуация | Что делает обработчик |
|---|---|
| ID `1001..1005` (цифры) | ASCII-код (`0x31='1'` … `0x35='5'`) кладётся в стек как аргумент, вызывается `safe.4010B1`, которая дописывает символ в буфер `0x403000` |
| ID `1006` (**Open**) | вызывается `safe.4010D3` — процедура проверки |
| `msg == WM_CLOSE` (`0x10`) | `EndDialog` |

Ставим бряк на `safe.4010D3` и продолжаем выполнение.

## 5. Найденный ключ

Считаем по схеме сравнений, подставляя ASCII-коды эталонной строки `"1234567890"` (`[edi+0]='1'=0x31`, `[edi+2]='3'=0x33`, `[edi+4]='5'=0x35`):

| # | Проверка | Вычисление | Символ |
|---|---|---|---|
| 1 | `ввод[0] == [edi+4]-1` | `0x35 - 1 = 0x34` | `'4'` |
| 2 | `ввод[2] == [edi+4]` | `0x35` | `'5'` |
| 3 | `ввод[1] == [edi+2]` | `0x33` | `'3'` |
| 4 | `ввод[4] == [edi+0]` | `0x31` | `'1'` |
| 5 | `ввод[5] == [edi+2]` | `0x33` | `'3'` |
| 6 | `ввод[3] == [edi+4]` | `0x35` | `'5'` |

Собираем по индексам ввода `[0..5]`:

```
ввод[0] = '4'
ввод[1] = '3'
ввод[2] = '5'
ввод[3] = '5'
ввод[4] = '1'
ввод[5] = '3'
```

> **Ключ: `4 3 5 5 1 3`** — нажимаем кнопки с этими цифрами в таком порядке, затем **Open**.

Для проверки: `lstrlenA` даёт `6` — проходим первую проверку; все шесть `cmp` совпадают — флаг `[0x403109]` остаётся `0`; `je 0x401176` не срабатывает — попадаем на `MessageBoxA` с `"Good Job."` / `"Yup"`.

## 6. Патч (опционально)

Если цель — не подобрать ключ, а заставить программу хвалить при любом вводе:

- **Вариант A:** в `safe.401185` заменить запись `1` в `[0x403109]` на `nop`-ы (или на запись `0`) — флаг никогда не выставится.
- **Вариант B:** в `0x40115C` заменить `je 0x401176` на `jmp 0x401176` — тогда поздравление не покажется никогда (обратный эффект, для теста).
- **Вариант C:** в `0x40115C` заменить `je` на `jne` — поздравление будет показываться при **провале** проверки, что удобно для отладки ветки MessageBox.

Крякми отличный для новичка: чистый диалоговый обработчик, понятное ветвление по `wParam`, аккуратная процедура валидации с прозрачной схемой сравнений и наглядный флаг результата. Нетривиальность в том, что ввод идёт кнопками (буфер `0x403000` наполняется через `safe.4010B1`), а не через `GetDlgItemText`/консоль — это заставляет не искать «поле ввода», а сразу читать логику обработчика.
